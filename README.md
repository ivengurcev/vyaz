# Vyaz (`@vyaz/core`)

**Vyaz (Вязь)** — компактный фреймворк для создания серверных React-приложений на Hono и esbuild.

Объединяет серверный рендеринг (SSR), клиентскую маршрутизацию, сборку, API и авторизацию в переиспользуемое ядро.

Основная задача — избавить приложения от повторяющегося инфраструктурного кода, сохраняя свободу в организации страниц, компонентов и бизнес-логики.

> **Статус:** проект находится в активной разработке и используется в собственных приложениях. Публичный API пока не стабилизирован.

## Возможности

- **SSR** — потоковый серверный рендеринг React через `renderToPipeableStream`.
- **Клиентский роутер** — переходы без перезагрузки страницы, динамические маршруты, History API.
- **Сборка** — отдельные browser- и SSR-бандлы через esbuild.
- **API** — декларативное описание HTTP-эндпоинтов на Hono.
- **Авторизация** — интеграция Auth.js через `@hono/auth-js`.
- **Контроль доступа** — защищённые страницы и API с пользовательскими проверками разрешений.
- **Начальные данные** — подготовка данных при SSR и передача их клиенту.
- **Стили** — CSS, SCSS, CSS Modules, PostCSS и Autoprefixer.
- **SVG** — импорт SVG в качестве React-компонентов через SVGR.
- **Настраиваемые layouts** — собственные HTML-, React- и auth-шаблоны.

## Технологии

| Технология | Назначение |
|---|---|
| React 19 | Интерфейс, SSR и гидрация |
| Hono | HTTP-сервер и API |
| esbuild | Клиентская и серверная сборка |
| Auth.js | Авторизация |
| Sass / PostCSS | Обработка стилей |
| SVGR | SVG-компоненты |

Проект использует JavaScript и ECMAScript Modules (ESM).

## Архитектура

Vyaz разделяет инфраструктуру и код приложения.

```text
Приложение
    ├── Страницы и компоненты
    ├── Маршруты
    ├── API
    ├── Авторизация
    ├── Бизнес-логика
    └── Конфигурация
            │
            ▼
       @vyaz/core
            ├── Hono runtime
            ├── SSR
            ├── Клиентский роутер
            ├── Сборка
            ├── Auth/API middleware
            └── React context
```

Ядро ничего не знает о предметной области конкретного приложения. Модели, роли, разрешения и бизнес-правила определяются на стороне приложения.

Главная точка входа — `createApp.mjs`.

### Жизненный цикл приложения

Первоначальная загрузка страницы:

```text
HTTP-запрос
    ↓
Hono
    ↓
Поиск маршрута
    ↓
Авторизация и проверка доступа
    ↓
Загрузка компонента
    ↓
Подготовка initialData
    ↓
React SSR
    ↓
HTML + данные приложения
    ↓
Гидрация React в браузере
```

После гидрации клиентский роутер обеспечивает переходы между страницами без полной перезагрузки.

Серверная и клиентская части используют общую структуру React-компонентов:

```jsx
<AppCore>
    <SiteApp>
        <CurrentRoute />
    </SiteApp>
</AppCore>
```

## Подключение

Пакет называется `@vyaz/core` и сейчас используется как часть локального workspace.

Приложение импортирует функциональность ядра через пакетные пути:

```js
import createApp from '@vyaz/core/createApp.mjs';
import ApplicationContext from '@vyaz/core/Context.js';
```

Способ подключения зависит от конфигурации workspace. Самостоятельный установочный сценарий для сторонних проектов пока не оформлен.

### Минимальный пример

Страница:

```jsx
// Pages/Home.jsx

export default function Home() {
    return <h1>Привет из Vyaz!</h1>;
}
```

Точка входа приложения:

```js
// server.mjs

import createApp from '@vyaz/core/createApp.mjs';

await createApp({
    PORT: 3000,
    PAGE_TITLE: 'Мой сайт',

    routes: [
        {
            path: '/',
            title: 'Главная',
            component: './Pages/Home.jsx',
        },
    ],

    api: [
        [
            '/hello',
            { method: 'GET' },
            () => ({ message: 'Привет из API!' }),
        ],
    ],
});
```

Сборка:

```bash
node server.mjs --build-public --build-ssr
```

Запуск:

```bash
node server.mjs --serve
```

По умолчанию сервер доступен по адресу `http://localhost:3000`.

API-эндпоинт из примера: `http://localhost:3000/api/hello`.

## Конфигурация

Настройки передаются непосредственно в `createApp()` и нормализуются в `utils/normalizeSettings.mjs`.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP-сервера |
| `SERVER_URL` | `http://localhost:PORT` | URL сервера |
| `OUTDIR` | `./dist` | Каталог сборки |
| `PUBLIC_PATH` | `/public` | Собранные клиентские ресурсы |
| `STATIC_PATH` | `/static` | Статические файлы workspace |
| `ASSET_PUBLIC_BASE` | `/uploads` | Публичные ресурсы |
| `API_ROOT` | `/api` | Префикс API |
| `AUTH_URL` | `/auth` | Префикс Auth.js |
| `AUTH_SIGNIN` | `AUTH_URL + /signin` | Страница входа |
| `PAGE_TITLE` | `''` | Заголовок по умолчанию |
| `LAYOUT_HTML` | `Layout/Layout.jsx` | HTML-шаблон SSR |
| `LAYOUT_APP` | `Layout/Application.jsx` | Корневой React-компонент |
| `LAYOUT_AUTH` | `''` | Шаблон авторизации (необязательный) |

Пути к layout-файлам можно переопределять на уровне приложения.

## Маршрутизация

Маршруты описываются единым массивом `routes`.

```js
const routes = [
    {
        path: '/',
        title: 'Главная',
        component: './Pages/Home.jsx',
    },
    {
        path: '/profile',
        title: 'Профиль',
        component: './Pages/Profile.jsx',
        isPrivate: true,
        getData: (c) => ({
            url: c.req.url,
        }),
    },
    {
        path: '/articles/:id',
        title: 'Статья',
        component: './Pages/Article.jsx',
    },
];
```

### Параметры маршрута

| Параметр | Назначение |
|---|---|
| `path` | URL маршрута |
| `component` | Путь к React-компоненту |
| `title` | Заголовок страницы |
| `isPrivate` | Требуется авторизация |
| `isServer` | Исключить маршрут из клиентской сборки |
| `getData` | Подготовить начальные данные |

Поддерживаются динамические сегменты URL, например `/articles/:id`.

### Серверная маршрутизация

На сервере маршруты регистрируются в Hono.

При совпадении маршрута ядро загружает компонент, выполняет проверки доступа и передаёт управление общему обработчику SSR.

Если несколько маршрутов совпадают, используется первый подходящий. Поэтому более конкретные маршруты следует располагать раньше динамических.

### Клиентская маршрутизация

При сборке создаётся клиентский роутер с динамическими импортами компонентов.

Навигация выполняется через `navigate()`, доступный в React-контексте приложения.

Роутер поддерживает:

- переходы без полной перезагрузки;
- `pushState` и `replaceState`;
- переходы назад и вперёд через `popstate`;
- динамическую загрузку компонентов.

Если маршрут не найден в клиентском роутере, выполняется обычный переход браузера.

## API

API описывается массивом кортежей:

```js
const api = [
    [
        '/articles',
        { method: 'GET' },
        async (c) => {
            return { articles: [] };
        },
    ],
    [
        '/articles',
        { method: 'POST' },
        async (c) => {
            const data = await c.req.json();

            return { received: data };
        },
    ],
];
```

Формат:

```js
[route, options, handler]
```

Поддерживаемые HTTP-методы: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.

По умолчанию используется `GET`.

Обработчик может вернуть:

- **Обычное значение** — автоматически преобразуется в JSON.
- **`Response`** — возвращается напрямую, сохраняя статус, заголовки и тело ответа.

### Контроль доступа к API

```js
[
    '/admin/users',
    {
        method: 'GET',
        permissions: ['users.read'],
    },
    async (c) => {
        return { users: [] };
    },
]
```

Защищённый API-эндпоинт определяется наличием одного из параметров:

- `private`
- `permissions`
- `permissionsAny`
- `roles`

Для таких эндпоинтов подключается проверка авторизации.

Дополнительная проверка разрешений выполняется через callback `hasAccess`, реализованный приложением. Сами по себе значения `roles` и `permissions` не определяют правила доступа.

## Авторизация

Авторизация подключается через Auth.js и является необязательной.

Приложение передаёт функцию `auth`, которая формирует конфигурацию Auth.js.

```js
await createApp({
    auth: ({
        AUTH_URL,
        AUTH_SECRET,
        CredentialsProvider,
    }) => ({
        providers: [
            CredentialsProvider({
                // Настройки провайдера
            }),
        ],
        secret: AUTH_SECRET,
        basePath: AUTH_URL,
    }),
});
```

Vyaz подключает Auth.js middleware и обработчики по пути `AUTH_URL`.

При наличии `LAYOUT_AUTH` также создаётся отдельная страница входа.

### Защищённые страницы

```js
{
    path: '/dashboard',
    component: './Pages/Dashboard.jsx',
    isPrivate: true,
}
```

Возможные сценарии:

| Состояние | Поведение |
|---|---|
| Авторизация отключена, публичный маршрут | Страница доступна |
| Авторизация отключена, приватный маршрут | HTTP 503 |
| Пользователь не авторизован | Перенаправление на страницу входа |
| Пользователь авторизован | Проверка `hasAccess`, если она задана |

Модель ролей и разрешений определяется приложением.

### Переменные окружения

Поддерживается загрузка `.env` через `process.loadEnvFile`.

Путь к файлу можно переопределить переменной `APP_ENV_FILE`.

## SSR и начальные данные

Vyaz использует `renderToPipeableStream` для серверного рендеринга React.

При первоначальном запросе сервер определяет маршрут, подготавливает необходимые данные, создаёт HTML и передаёт результат клиенту.

В браузере выполняется гидрация через `hydrateRoot`.

### Явная подготовка данных

Для маршрута можно определить `getData`:

```js
{
    path: '/profile',
    component: './Pages/Profile.jsx',
    getData: async (c) => ({
        requestedAt: Date.now(),
    }),
}
```

Результат передаётся в `initialData`.

### Автоматическая подготовка данных

Дополнительно реализован экспериментальный механизм обнаружения зависимостей компонентов от начальных данных.

Перед SSR ядро анализирует исходный код компонента маршрута и его локальные импорты.

Например, если компонент использует:

```js
initialData.userProfile
```

ядро пытается найти соответствующий GET-эндпоинт:

```text
initialData.userProfile
        ↓
/user-profile
```

Найденный эндпоинт вызывается через внутренний запрос к Hono, а полученный результат добавляется в `initialData`.

Поддерживается сопоставление по полному имени маршрута или его завершающему сегменту.

**Ограничения текущей реализации:**

- Анализ основан на поиске текстовых обращений к `initialData`.
- Анализируются JavaScript-файлы и доступные локальные импорты.
- Автоматически вызываются только GET-эндпоинты без динамических сегментов.
- Анализ исходников выполняется во время серверного запроса.
- При клиентской навигации автоматическое обновление `initialData` не выполняется.

Механизм находится в разработке и может измениться.

## React-контекст

`Context.js` предоставляет общий контекст приложения.

Доступные значения:

| Значение | Назначение |
|---|---|
| `routeComponent` | Компонент текущего маршрута |
| `user` | Текущий пользователь |
| `setUser` | Изменение состояния пользователя |
| `initialData` | Начальные данные |
| `pathname` | Текущий путь |
| `navigate` | Клиентская навигация |

Контекст создаётся в `Layout/ApplicationCore.jsx`.

### `useFetch`

В ядре также имеется хук `useFetch(path)`.

Он возвращает Promise результата запроса и функцию повторного запроса.

```js
const [query, refetch] = useFetch('/api/articles');
```

Хук представляет собой минимальную обёртку над `fetch` и не является полноценной библиотекой управления серверным состоянием.

## Система сборки

Vyaz использует esbuild для раздельной сборки браузерной и серверной частей.

### Browser build

`builder/buildPublic.mjs`

Включает:

- клиентскую точку входа;
- React-гидрацию;
- клиентский роутер;
- компоненты приложения;
- стили и ресурсы;
- разделение кода на чанки.

Поддерживаются CSS, SCSS, CSS Modules, Autoprefixer и SVG-компоненты.

### SSR build

`builder/buildSSR.mjs`

Создаёт серверные модули:

```text
dist/
└── ssr/
    ├── Layout.js
    ├── SiteApp.js
    ├── AppCore.js
    ├── CurrentRoute.js
    └── routes.js
```

React и React DOM остаются внешними зависимостями серверной сборки.

### CLI-флаги

| Флаг | Назначение |
|---|---|
| `--build-public` | Собрать клиентскую часть |
| `--build-ssr` | Собрать SSR-модули |
| `--serve` | Запустить HTTP-сервер |
| `--watch` | Следить за изменениями клиентского кода |
| `--minify` | Минифицировать клиентскую сборку |
| `--sourcemap` | Генерировать sourcemaps |

Флаги можно комбинировать:

```bash
node server.mjs --build-public --build-ssr --serve
```

Или запускать сборку с отслеживанием изменений:

```bash
node server.mjs --build-public --watch --sourcemap
```

## Разработка и тестирование

Для тестирования используется встроенный `node:test`.

Запуск тестов из корня пакета при установленных зависимостях:

```bash
node --test test/*.test.mjs
```

В настоящее время тестами покрыты:

- серверная маршрутизация и обработка пересекающихся маршрутов;
- преобразование API-ответов в JSON и передача готовых объектов `Response`.

Проверки сборки и интеграционные тесты пока ограничены.

## Принципы разработки

- **Переиспользуемость.** Ядро не зависит от бизнес-логики конкретных приложений.
- **Минимальная сложность.** Новые абстракции добавляются при наличии практической необходимости.
- **Явные точки интеграции.** Приложение передаёт маршруты, API, конфигурацию и callbacks.
- **Разделение ответственности.** Сборка, серверный код и React runtime находятся в отдельных модулях.
- **Без преждевременной совместимости.** Публичный API ещё не стабилизирован, поэтому изменения не требуют сохранения устаревших контрактов.

Подробные правила работы с исходным кодом приведены в `AGENTS.md`.

## Текущее состояние

Vyaz используется как собственное инфраструктурное ядро и продолжает развиваться.

Основные направления дальнейшей работы:

- совершенствование механизма начальных данных;
- согласование загрузки данных между SSR и клиентской навигацией;
- расширение тестового покрытия;
- улучшение документации и подключения новых приложений.

Проект пока не позиционируется как готовая универсальная альтернатива существующим React-фреймворкам.
